## 1. 目的

M5Stack AtomS3 を電池駆動またはバスパワー制約下で運用したときの電力見積り根拠を得ることを目的とする。
具体的には次の 3 点を明らかにする。

1. 起動シーケンス（電源投入からアプリ動作開始まで）に要する電荷量とピーク電流
2. WiFi 接続維持中の定常電流と、省電力モード設定による差
3. MQTT 1 回の Publish あたりの電荷量（mC）と、送信間隔から逆算した電池寿命

最終的なアウトプットは「1 回の計測送信サイクルあたりの消費電荷量（mC）」と「電源設計に必要なピーク電流値（A）」の 2 つ。
この 2 値が決まれば、電池容量選定とレギュレータ／バルクコンデンサの容量選定ができる。

## 2. 評価範囲

### 対象に含めるもの／含めないもの

| 区分 | 内容 |
| --- | --- |
| 含む | AtomS3 ボード単体（MCU + LCD + 内蔵レギュレータ + USB-シリアル）の入力電流 |
| 含む | ファーム側の設定（CPU クロック、WiFi 省電力モード、LCD バックライト）による感度 |
| 含まない | Grove 経由で接続する外部センサ／アクチュエータの消費電流 |
| 含まない | 温度依存性（常温 25±5℃ での評価とし、温度加速は別計画とする） |
| 含まない | 長期エージング（連続 24 時間超の耐久計測） |

### 前提条件（実施前に確定させる）

- 対象ファームウェアのバージョンとビルド設定を 1 つに固定する（ESP-IDF or Arduino-ESP32、いずれもバージョンを記録）。
- 接続先 AP と MQTT ブローカを固定する。電波環境が変わると結果が比較できなくなるため、同一 AP・同一設置位置で通しで計測する。
- DUT は同一個体を通して使う。個体ばらつきを見る場合は 3 台以上を別途用意する（§8 の派生項目）。

## 3. 計測系の構成

### 3.1 PPK2 の基本仕様

ユーザーガイド（v1.0.1, 4461_012）記載の主要諸元を抜粋する。計測系の設計判断はここが根拠になる。

| 項目 | 値 |
| --- | --- |
| 測定電流範囲 | 500 nA〜1 A（約 200 nA まで検出可能） |
| サンプリングレート | 100 kS/s（時間分解能 10 µs） |
| 供給電圧（Source meter 時） | 0.8〜5.0 V（アプリから可変） |
| 外部供給電圧（Ampere meter 時） | 0.8〜5.0 V（無調整でそのまま DUT へ通る） |
| **DUT 許容電流（Ampere meter）** | **最大 1 A（連続）** |
| **DUT 許容電流（Source meter）** | **最大 600 mA** |
| 定格電力 | 5 W |
| 動作温度 | 5〜40℃ |
| ロジックポート | 8 ch（D0〜D7）、VCC 1.65〜5.5 V |
| デジタル入力サンプリング | 100 kHz（帯域は typ. 50 kHz） |
| 平均電流確度 | 全体で ±20% 以内（レンジ別は下表） |
| 計測エンジン | nRF52840 の ADC で直列抵抗の電圧降下を測定。5 レンジを自動切替。校正値は基板上 EEPROM に保持 |

レンジごとの分解能と確度は次のとおり。**同じ PPK2 でもレンジによって分解能が 5000 倍違う**ので、どの状態がどのレンジに入るかを意識して計測計画を立てる必要がある。

| レンジ | 分解能 | 確度（平均値） | オフセット | 本評価で該当する状態 |
| --- | --- | --- | --- | --- |
| R1：200 nA〜50 µA | 0.2 µA | ±10% | ±2% | ディープスリープ |
| R2：50 µA〜500 µA | 0.5 µA | ±10% | ±2% | ライトスリープ |
| R3：500 µA〜5 mA | 5 µA | ±10% | ±2% | （該当少） |
| R4：5 mA〜50 mA | 50 µA | ±10% | ±2% | モデムスリープ、LCD OFF アイドル |
| R5：50 mA〜1000 mA | **1000 µA（＝1 mA）** | **±15%** | ±5% | WiFi 送受信、LCD バックライト ON |

WiFi 送受信は必ず R5 に入り、**分解能 1 mA・確度 ±15%** になる。ここは PPK2 の一番粗い領域なので、絶対値の精度を求めすぎず「条件間の相対比較と電荷量の積算」に用途を割り切る。

もう一つ注意すべきは **レンジ切替点付近の挙動**で、ユーザーガイドのトラブルシューティングにも「消費電流が切替点近傍にあるとレンジ間で高速に切り替わり、測定誤差や波形の乱れを起こす」と明記されている。AtomS3 のアイドル電流は 50 mA（R4/R5 境界）付近に乗る可能性が高いので、アイドル状態の波形が不自然に暴れる場合はこれを疑うこと。LCD バックライトの ON/OFF で境界をまたぐ場合は、両方の条件でこの現象の有無を記録する。

### 3.2 PPK2 の動作モードの選定

PPK2 には給電しながら測る Source meter モードと、外部電源と DUT の間に直列に入る Ampere meter モードがある。本評価では **Ampere meter モードを主とする**。

決め手は許容電流で、Source meter モードの DUT 許容電流は **600 mA まで**（かつ DUT が 400 mA を超え得る場合はユーザーガイドが「USB POWER ONLY 側に 1 A 以上供給できる外部 USB 電源を追加すること」を推奨している）。対して Ampere meter モードは連続 1 A まで許容される。ESP32-S3 の WiFi 送信ピークは数百 mA 級で 600 mA に迫るため、余裕を取って Ampere meter モードを選ぶ。

加えて、PPK2 の内蔵レギュレータから供給すると出力インピーダンスの影響で送信ピーク時に電圧が落ち込み、ブラウンアウトリセットを踏む懸念もある。ユーザーガイドも Ampere meter モードについて「USB 給電でも足りるが、確度を上げるならラボ用電源を推奨」としているので、外部の安定化電源から供給し PPK2 は電流経路にのみ挿入する構成にする。

消費電流の小さいスリープ状態を R1/R2 の分解能で見たいケース（§8 の派生項目）では Source meter モードも併用する。この条件なら電流が小さいので 600 mA 制限は問題にならない。どちらのモードで取ったデータかは必ず記録に残す。

### 3.3 コネクタと結線

PPK2 のコネクタは次のとおり（キットには 4 ピン電流測定ケーブルと 10 ピンロジックポートケーブルが付属する）。

| コネクタ | 用途 |
| --- | --- |
| VIN | 外部電源入力。**Ampere meter モードでのみ使用** |
| VOUT | DUT への電圧出力 |
| GND | DUT との GND 接続（VIN 側・VOUT 側の 2 か所） |
| USB DATA/POWER | PC との通信＋PPK2 本体電源。**常時接続が必須** |
| USB POWER ONLY | 追加給電用。Source meter モードで 400 mA 超のときのみ必要 |
| LOGIC PORT | VCC / GND / D0〜D7 |

本評価（Ampere meter モード）の結線は以下。

| 接続元 | 接続先 |
| --- | --- |
| 外部安定化電源 5V(+) | PPK2 **VIN** |
| PPK2 **VOUT** | AtomS3 の 5V 入力（USB-C VBUS ブレイクアウト経由） |
| 外部電源 GND / AtomS3 GND | PPK2 **GND** |
| PPK2 **USB DATA/POWER** | 計測 PC（USB ハブ・ドッキングステーションを介さず直挿し） |

注意点が 3 つある。

1. **GND は Ampere meter モードでも必ず PPK2 に接続する。** ユーザーガイドのトラブルシューティングで明示されている典型的な失敗要因。
2. **PPK2 は負の電流を測定できない。** VIN/VOUT を逆に結線すると「何も測れない」状態になる。極性は結線後に必ず確認する。
3. **USB ハブ／ドッキングステーション経由は避ける。** グラフ描画が遅くなる・取りこぼす要因になると公式に案内されている。100 kS/s で長時間回すので PC 側の CPU とディスク空き容量も確保しておく。

```text
                        ┌──────────── PPK2 ────────────┐
 [外部安定化電源 5V] ───→│ VIN                     VOUT │───→ [AtomS3 5V 入力]
                        │                              │
                    ────│ GND                      GND │────  共通 GND
                        │                              │
      [計測 PC] ←──USB──│ USB DATA/POWER               │
                        │                              │
                        │ LOGIC PORT                   │
                        │  VCC ←── AtomS3 3.3V         │
                        │  GND ←── AtomS3 GND          │
                        │  D0〜D2 ←── AtomS3 GPIO      │（イベントマーカ）
                        └──────────────────────────────┘
```

### 3.4 計測点

計測点は 2 パターン想定し、まず A を実施する。B は A の結果を見て必要と判断した場合に実施する。

| パターン | 挿入位置 | 測れるもの | 備考 |
| --- | --- | --- | --- |
| A：5V 入力側 | USB-C の VBUS ライン、または Grove ポートの 5V ピン | ボード全体（LDO 損失・USB-シリアル IC・LCD 含む）の実消費 | 電源設計に直結する値。基本はこちら |
| B：3.3V レール | 基板上の 3.3V ライン | MCU + 無線モジュール主体の消費 | パターンカットまたはインダクタ／0Ω 除去を伴うハード改造が必要。破壊を伴うため実施可否を要判断 |

パターン A の挿入方法は、USB 電流測定用のブレイクアウト基板（VBUS を切り離せるタイプ）を使う。
Grove ポートの 5V ピンから逆給電する方法も取り得るが、**AtomS3 の Grove 5V ピンが USB VBUS とどう接続されているか（直結か、保護ダイオード／FET 経由か）を回路図で先に確認すること**。ダイオード 1 個入っているだけでも電圧降下分が結果に乗るため、確認できるまでは USB-C 側での挿入を優先する。

### 3.5 イベントマーカ（ロジックポートによる区間の切り出し）

各フェーズの境界を後から目視で当てるのは精度が出ないため、DUT 側の GPIO を PPK2 のロジックポート（D0〜D7、最大 8 ch 同時）に接続し、ファーム側でフェーズごとにトグルさせる。ロジックポートを使うときは Dx だけでなく **VCC ピンに DUT の VCC、GND ピンに DUT の GND を必ず接続する**（ユーザーガイド 6.4 の指定）。VCC の許容範囲は 1.65〜5.5 V なので、AtomS3 の 3.3V を入れる。

| ロジック ch | 割り当て | 立ち上げ／立ち下げのタイミング |
| --- | --- | --- |
| D0 | アプリ起動完了 | `app_main` 到達時に H |
| D1 | WiFi 接続区間 | 接続開始で H、`IP_EVENT_STA_GOT_IP` で L |
| D2 | MQTT Publish 区間 | `publish()` 呼び出し直前で H、送信完了コールバックで L |

デジタル入力のサンプリングは 100 kHz、帯域は typ. 50 kHz。マーカのパルス幅が数十 µs を下回ると取りこぼす可能性があるため、**マーカは最低でも 100 µs 以上の幅を確保する**。区間そのものが短い場合（キープアライブ等）は、マーカを区間終了後もしばらく H に保持するのではなく、区間の前後にプリアンブル的な固定幅パルスを打って位置を特定する方法を取る。

使用する GPIO は Grove の G1 / G2 と底面ピンから空いているものを選ぶ。LCD・USB に割り当てられているピンと衝突しないよう、ピンアサインは事前に回路図で確認する。

### 3.6 計測条件（サンプリング）

| 項目 | 設定 |
| --- | --- |
| サンプリングレート | 100 kS/s（PPK2 最大、時間分解能 10 µs）。長時間の定常観測は平均化して低レートに落とす（最低 1 sample/s まで下げられる） |
| 供給電圧 | 5.00 V（主条件）／3.30 V（パターン B 実施時） |
| 計測時間 | 起動：電源投入前 1 秒 〜 起動完了後 5 秒<br>WiFi 定常：60 秒以上<br>MQTT：1 Publish を 30 回以上含む区間 |
| 繰り返し数 | 各条件 5 回（N=5）。平均・標準偏差・最大値を記録 |
| 環境 | 室温 25±5℃、AP との距離を固定（設置位置を写真で記録）。PPK2 の動作温度は 5〜40℃ |

100 kS/s は 10 µs 刻みなので、WiFi の 1 パケット送信そのものの波形を細部まで追うには足りない。PPK2 で見るのは「区間の平均電流と電荷量」および「ms オーダーのピーク包絡線」までと割り切る。µs オーダーの立ち上がり波形が必要になった場合は、電流プローブ＋オシロを別途手配する（§9 リスク参照）。

Power Profiler アプリ v4.0.0 以降は収録データを RAM ではなくディスクに書くようになっており、録画時間の上限は実質的にディスク空き容量で決まる。100 kS/s の長時間収録では容量を食うため、事前に空き容量を確保し、アプリの詳細設定でセッションファイルの保存先とディスク逼迫時の停止条件を設定しておく。

## 4. 計測シナリオ

### シナリオ 1：起動中

電源投入（VBUS 印加）からアプリ動作開始までを計測する。
起動は ROM ブートローダ → 2nd ステージブートローダ → アプリ初期化 → 周辺初期化（LCD／WiFi スタック）と段階が分かれるので、区間を分けて電荷量を出す。

| 区間 | 開始 | 終了 | 取得値 |
| --- | --- | --- | --- |
| 1-a 全体 | VBUS 印加 | D0 立ち上がり（`app_main` 到達） | 所要時間、平均電流、ピーク電流、電荷量 |
| 1-b 突入電流 | VBUS 印加 | +10 ms | ピーク電流、パルス幅 |
| 1-c 周辺初期化 | D0 立ち上がり | LCD 表示完了・WiFi スタック起動完了 | 所要時間、平均電流、電荷量 |

突入電流（1-b）はボード上のバルクコンデンサへの充電電流なので、電源側の電流制限やヒューズ選定に効いてくる。ここは電源投入方法（機械式スイッチ／電子ロードのステップ）で値が変わるため、投入方法を固定して記録すること。

さらに派生条件として、ディープスリープからの復帰起動も同じ枠組みで計測する。コールドブートとの差が「間欠動作でスリープを使う価値」の定量値になる。

### シナリオ 2：WiFi 通信中

WiFi は状態によって消費電流の傾向が大きく変わるので、以下に分けて計測する。

| 区間 | 内容 | 取得値 |
| --- | --- | --- |
| 2-a アソシエーション | スキャン〜認証〜DHCP で IP 取得まで | 所要時間、平均電流、電荷量 |
| 2-b 接続維持（アイドル） | IP 取得後、通信なしで 60 秒放置 | 平均電流、ビーコン受信ピークの周期と振幅 |
| 2-c 連続送信 | 一定レートで TCP 送信を継続（スループット固定） | 平均電流、ピーク電流 |
| 2-d 受信主体 | 一定レートで受信を継続 | 平均電流 |

2-b は WiFi 省電力モードの設定で結果が大きく変わる。以下 3 条件で振って比較する。

- `WIFI_PS_NONE`（省電力なし、常時受信）
- `WIFI_PS_MIN_MODEM`（DTIM ごとに起床）
- `WIFI_PS_MAX_MODEM`（listen interval を延ばす）

DTIM 間隔は AP 側の設定なので、AP の DTIM 値を記録する（AP 側を変更できるなら DTIM=1 と DTIM=3 の 2 条件を取ると効果が見える）。

### シナリオ 3：MQTT 送信中

MQTT は「接続確立」と「1 回の Publish」を分けて評価する。実運用の電池寿命を左右するのは後者。

| 区間 | 内容 | 取得値 |
| --- | --- | --- |
| 3-a CONNECT | TCP 接続 〜 MQTT CONNACK 受信まで（TLS 使用時はハンドシェイク含む） | 所要時間、電荷量 |
| 3-b PUBLISH | D2 の H 区間（送信開始〜完了コールバック） | 1 回あたりの所要時間、平均電流、ピーク電流、電荷量（mC） |
| 3-c キープアライブ | PINGREQ/PINGRESP 1 往復 | 所要時間、電荷量 |

3-b は以下の条件を振る。

| 因子 | 水準 |
| --- | --- |
| QoS | 0 / 1 |
| ペイロードサイズ | 32 B / 256 B / 1 kB |
| TLS | 無効 / 有効（TLS 有効時はハンドシェイクの電荷量が 3-a に乗る点に注意） |

TLS ハンドシェイクは公開鍵演算で CPU が張り付くうえ往復も多いので、間欠接続（毎回 CONNECT する運用）と接続維持（セッションを張りっぱなしにする運用）でどちらが得かの判断材料になる。この比較は §7 の計算モデルで扱う。

## 5. 制御因子と固定条件

結果を比較可能にするため、シナリオごとに振る因子以外は下表で固定する。固定値は計測ログのヘッダに必ず書き込む。

| 因子 | 既定の固定値 | 備考 |
| --- | --- | --- |
| CPU クロック | 240 MHz | 感度確認として 160 / 80 MHz も別条件で取得 |
| LCD バックライト | OFF | AtomS3 は LCD 付きのため、ON/OFF 差は無視できない。ON 時の輝度も水準化する |
| LCD 表示更新 | 停止 | 描画中は SPI + バックライトで上乗せされる |
| WiFi 送信出力 | 既定値（ファームの設定値を記録） | 出力を下げると消費も下がるので、感度項目として別途評価 |
| WiFi 規格 / チャネル | 2.4 GHz、AP 設定に従う（記録する） | |
| RSSI | 計測前後で記録し、変動が大きい場合はデータを棄却 | |
| 供給電圧 | 5.00 V | |
| USB-シリアル IC | 動作状態（USB 接続の有無で変わる） | ログ出力を UART に流すかどうかも固定する |

シリアルログ出力は CPU 時間を食うので、計測時はログレベルを本番相当まで落とすこと。デバッグログを出したままだと起動時間も電荷量も過大に出る。

## 6. 事前想定値（実測で置き換える）

計測レンジ設定と安全確認のための目安。ESP32-S3 のデータシート上の代表値をベースにした参考値で、ボード全体（LDO 効率・LCD・USB-シリアル IC を含む）ではこれより増える。**実測後に本表は実測値へ差し替える。**

| 状態 | 参考オーダー（チップ 3.3V 換算） | ボードでの上振れ要因 |
| --- | --- | --- |
| WiFi 送信ピーク | 数百 mA 級 | LDO 損失、バルクコンデンサへの補充電 |
| WiFi 受信 | 100 mA 前後 | 同上 |
| CPU 動作・無線停止（モデムスリープ） | 数十 mA | LCD バックライト ON で大幅増 |
| ライトスリープ | 数百 µA | LDO 静止電流、USB-シリアル IC の待機電流が支配的になり得る |
| ディープスリープ | 数 µA〜数十 µA | 同上。ボードレベルでは桁が変わる可能性が高い |

PPK2 の DUT 許容電流は Ampere meter モードで連続 1 A。WiFi 送信ピークがこれを超える見込みは低いが、突入電流（1-b）は超え得るため、初回は必ずレンジオーバーの有無を確認してから本計測に入る。
Source meter モードを併用する場合、DUT 許容電流は **600 mA** に下がる。さらに DUT が 400 mA を超え得る条件では USB DATA/POWER 側の給電だけでは足りず、USB POWER ONLY 側に 1 A 以上供給できる USB 電源の追加接続が必要になる（PPK2 自身の回路も約 50 mA 消費する）。本評価で Source meter モードを使うのはスリープ計測に限定するので、この制約には触れない想定。

## 7. データ処理と評価指標

### 算出する値

各区間について次を算出する。

- 所要時間 T [ms]
- 平均電流 I_avg [mA]
- ピーク電流 I_peak [mA]（および発生位置）
- 電荷量 Q = I_avg × T [mC]
- エネルギー E = Q × V [mJ]（V は供給電圧）

### 電池寿命モデル

送信周期 T_cycle でスリープ・起動・送信を繰り返す運用を想定し、1 サイクルの電荷量を次式で見積もる。

```text
Q_cycle = Q_wakeup + Q_wifi_assoc + Q_mqtt_connect + Q_publish + I_sleep × T_sleep
推定稼働時間 [h] = 電池容量 [mAh] × 3600 / Q_cycle [mC] × T_cycle [s] / 3600
```

接続維持運用の場合は `Q_wifi_assoc` と `Q_mqtt_connect` が消え、代わりにアイドル区間の平均電流（2-b）とキープアライブ（3-c）が乗る。両者を同じ式で比較し、送信周期に対する損益分岐点を求める。この分岐点が本評価の結論の一つになる。

電池容量は公称値をそのまま使わず、電池の内部抵抗・カットオフ電圧・温度によるディレーティングを別途かけること。本計画では電荷量の実測までを範囲とし、ディレーティング係数の決定は電源設計側に委ねる。

### 保存するデータ

- PPK2 の生データ（`.ppk2` セッションファイル）を条件ごとに保存
- CSV エクスポート（区間の選択範囲のみ。デジタルチャネル列を含む）
- 条件記録シート（§5 の因子一覧に実値を記入したもの）
- スクリーンショット（波形の代表例）

ファイル名の規約は `02-001_<シナリオ番号>_<条件略号>_run<N>` とする（例：`02-001_3b_qos1_256B_tls_off_run3`）。

## 8. 実施手順

### 8.1 事前準備（初回のみ）

1. PC に **nRF Connect for Desktop** をインストールし、そのランチャーから **Power Profiler アプリ**をインストールする。対応 OS は Windows 8/10、macOS、Linux。
2. PPK2 を micro-USB ケーブルで PC に接続する（USB DATA/POWER 側）。PPK2 は USB CDC ACM で通信するため専用ドライバのインストールは不要。
3. Power Profiler アプリを起動し、デバイスを選択する。ファームウェアの更新を促された場合は適用する（アプリのバージョンとファームウェアのバージョンを記録しておく）。
4. アプリの詳細設定でセッションファイルの保存先を、十分な空き容量があるドライブに変更する。

### 8.2 計測系の構築とセルフチェック

1. §3.3 の結線図どおりに配線する。**VIN/VOUT の向き**と**GND の接続**をテスタで確認してから通電する。
2. アプリでモードを **Ampere meter** に設定する（モード選択はアプリ側で行う。ハード側のスイッチではない）。PPK2 本体の LED はモードによって色が変わるので、実機で「どちらの色がどちらのモードか」を一度確認し、以後は目視でモード誤りを防ぐ。
3. DUT 未接続の状態でサンプリングを開始し、読み値がノイズレベル（〜数百 nA）に収まることを確認する。ここで有意な電流が出ていたら結線かモード設定を疑う。
4. **既知抵抗による確度チェック**：5.0 V に対して既知抵抗（例：100 Ω → 50 mA、10 Ω → 500 mA）を負荷として接続し、オームの法則から求まる値と読み値を突き合わせる。R5 レンジの確度が ±15% なので、この範囲に収まっていれば正常と判断する。この結果は校正記録として残す。
5. **ロジックポートの疎通確認**：AtomS3 で D0〜D2 に固定周期のパルス（幅 1 ms 程度）を出力させ、アプリのデジタルチャネル表示に正しく現れることを確認する。
6. **レンジ切替点の確認**：AtomS3 をアイドル状態にして波形を観察し、R4/R5 境界（50 mA 付近）でレンジがばたついていないかを見る。ばたつく場合は §9 の対策を検討し、そのことを計測記録に明記する。

### 8.3 ファームウェアの準備

1. フェーズマーカ用 GPIO トグルを実装する（§3.5 の割り当て、パルス幅 100 µs 以上）。
2. ログレベルを本番相当まで落とす。
3. 条件切り替え（省電力モード、QoS、ペイロードサイズ、TLS 有無、CPU クロック）をビルドフラグまたは起動時パラメータで切り替えられるようにする。
4. ビルド設定とバージョンを記録する。

### 8.4 アプリ操作手順（ビューの使い分け）

Power Profiler アプリには 2 つのビューがあり、本評価では取りたいものによって使い分ける。

| ビュー | 性格 | 本評価での用途 |
| --- | --- | --- |
| **Data Logger** | 連続収録。長時間の電流推移をそのまま記録する | シナリオ 2-b（WiFi アイドル 60 秒）、2-c/2-d（連続送受信）、シナリオ 3 の Publish 繰り返し |
| **Real Time**（オシロスコープ的） | トリガ条件成立時の前後を切り出して詳細に見る | シナリオ 1（起動・突入電流）、シナリオ 3-b の 1 Publish 波形 |

Real Time ビューのトリガには次が使える（アプリ v4.3.0 以降）。

- **アナログトリガ**：電流のしきい値。立ち上がりエッジ／立ち下がりエッジを選択できる。
- **デジタルトリガ**：デジタルチャネル（D0〜D7）の状態を条件にできる。**本評価ではこちらを主に使う**。マーカ GPIO の立ち上がりで確実に同じ区間を切り出せるため、シナリオ間・試行間の再現性が上がる。
- **プリトリガオフセット**：トリガ成立前にどれだけ遡って記録するかを指定できる。起動計測（トリガ＝D0 の立ち上がり＝アプリ起動完了）では、遡って電源投入時点まで含める必要があるため、想定起動時間より十分長いプリトリガ長を設定する。

計測ごとの操作は次の流れ。

1. サンプリングレートと収録時間を設定する（起動・Publish は 100 kS/s、長時間の定常観測はレートを落とす）。
2. Data Logger の場合はサンプリング開始 → 対象動作を実行 → 停止。Real Time の場合はトリガ条件を設定して待機 → 対象動作を実行。
3. チャート上でマーカ（デジタルチャネル）の立ち上がり／立ち下がりを目印に区間を選択する。選択範囲の統計（平均電流・最大値・電荷量・時間）がウィンドウに表示されるので、これを記録シートへ転記する。
4. セッションを `.ppk2` 形式で保存する。ファイル名は §7 の規約に従う。
5. 必要に応じて CSV エクスポートする。エクスポート時に「全サンプル／表示ウィンドウ内／選択範囲」を選べるので、**基本は選択範囲のみ**を出す（100 kS/s の全サンプルを CSV にすると数百万行になり扱いづらい）。デジタルチャネルも CSV に含まれるので、後段のスクリプト処理で区間を機械的に切り出せる。

### 8.5 計測の実施

1. シナリオ 1（起動）を N=5 で計測
2. シナリオ 2（WiFi）を条件ごとに N=5 で計測
3. シナリオ 3（MQTT）を条件ごとに N=5 で計測
4. データ処理・レポート作成

条件数 × N=5 で試行回数がかさむため、手作業が辛くなった場合は自動化を検討する。PPK2 は USB シリアル経由で制御できるため、非公式ながら Python から PPK2 を直接叩けるライブラリ（IRNAS 製 `ppk2-api`、GPLv2）がある。DUT 側のシリアル制御と組み合わせれば「条件を書き込む → 計測開始 → 動作させる → 停止 → 保存」を回せる。ただし公式サポート外なので、**自動化した場合は必ず一部条件を GUI での手動計測と突き合わせて値が一致することを確認する**こと。

### 8.6 派生項目（余力があれば実施）

- ディープスリープ／ライトスリープの実消費（Source meter モード、低レンジ）
- LCD バックライト輝度と消費電流の関係
- WiFi 送信出力設定を下げたときの消費と通信成功率のトレードオフ
- 個体ばらつき（3 台以上での比較）
- AtomS3 Lite（LCD なし）との比較

## 9. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| WiFi 送信の突入で電圧降下 → ブラウンアウトリセット | 起動を繰り返して計測不能 | Ampere meter モードで外部安定化電源から供給。それでも落ちる場合は DUT 直近にバルクコンデンサを追加（追加した容量値を記録し、突入電流計測の結果には影響する旨を注記） |
| 100 kS/s では µs 級の波形が追えない | パケット単位の詳細解析ができない | 本計画は区間平均・電荷量までを対象と明記。詳細波形が必要になったら電流プローブ＋オシロを別手配 |
| PPK2 の DUT 許容電流超過（Ampere meter 1 A / Source meter 600 mA） | 突入電流が飽和して過小評価。機器保護の観点でも避けたい | 初回に必ずレンジオーバー確認。Source meter は低電流条件に限定。超える場合はシャント＋オシロに切り替え |
| R5 レンジ（50 mA〜1 A）の分解能 1 mA・確度 ±15% | WiFi 送信区間の絶対値精度が出ない | 絶対値ではなく条件間の相対比較と電荷量積算に用途を限定。既知抵抗による確度チェック結果を報告書に併記 |
| レンジ自動切替点（特に 50 mA 付近）でのチャタリング | アイドル区間の波形が乱れ、平均値に誤差が乗る | 切替点を跨がない条件（LCD バックライト OFF 等）でも取得して比較。発生した場合は記録に明記し、該当区間の平均値は参考値扱いにする |
| ロジックマーカのパルス幅不足（デジタル入力帯域 typ. 50 kHz） | 区間マーカを取りこぼし、切り出しができない | マーカ幅は 100 µs 以上を確保。事前の疎通確認（§8.2-5）で必ず検証 |
| ディスク空き容量不足による収録停止 | 長時間計測が途中で切れる | 事前に空き容量を確保。アプリの詳細設定で保存先とディスク逼迫時の挙動を設定。長時間の定常観測はサンプリングレートを落とす |
| 電波環境の変動（近隣 AP の混雑） | 再現性が取れずばらつきが大きい | 同一時間帯・同一位置で通し計測。RSSI とリトライ回数を記録し、外れ値は棄却して再計測 |
| Grove 5V ピンからの逆給電が保護素子経由 | 電圧降下・電流経路の誤り | 回路図で接続を確認するまで USB-C 側での挿入を優先 |
| パターン B（3.3V レール）のハード改造 | DUT を破壊し評価継続不能 | 予備機を確保してから実施。A の結果で目的を満たせるなら B は実施しない |
| MQTT ブローカ側の応答遅延 | Publish 区間の時間が伸びて電荷量が過大 | ブローカをローカルに立てる条件と実運用ブローカの条件を分けて計測 |
